# Adversarial Specialist Debate — Issue #68

**Executed:** ten real specialist subagents, in two waves, 2026-11-11. No fictional agents. A1–A4 and B1–B2 worked independently before C1/C2 cross-examination and D1/D2 repo reconciliation.

## Round 1 — independent positions

- **A1 Commercial/value chains:** separate seller, owner, custodian, fulfiller, issuer, recipient and accounting entity; agreements and reversals are shared infrastructure.
- **A2 Operations/roles:** task queues and local execution must coexist with maker-checker, stock conservation and explicit close/reconciliation.
- **A3 Verticals:** industry packs may add states/validation/views but cannot fork parties, sites, work orders, stock or journals; regulated sectors begin research-only.
- **A4 Risk/global:** locale is not jurisdiction; offline is bounded intent; approval binds payload; restore proof—not upload—is backup acceptance.
- **B1 Enterprise:** strongest pattern is scoped document lineage, role/data separation, effective-dated workflows and compensation for nontransactional adapters.
- **B2 Modular/vertical:** best UX is fast counter/mobile work plus deep reconciliation; “free/installed/connected” never proves zero-cost or operational readiness.
- **C1 Architect:** modular monolith, canonical stock/auth/approval/journal boundaries, additive bridges, no arbitrary Studio execution or automatic dual-write.
- **C2 UX/Operations:** task-led role workspaces, Quick/Advanced on one engine, BN/EN contextual guidance, visible pending/conflict/incomplete states and exception recovery.
- **D1 Repo forensic:** PR #7 exact head is green synthetic evidence; current PR #60 head is not all-green and differs from recorded green SHA; Claude namespaces and shared engines are protected.
- **D2 Data/security:** `org_scope_on` remains blocked; signed Auth is absent; `partner_calculate()` has an all-location business-scope defect; PR #27 owns integration ports.

## Round 2 — cross-examination

| Challenge | Resolution |
|---|---|
| Task verbs can hide quote/order/dispatch/invoice/payment effects | Task labels resolve to typed workflow steps with the next committed effect shown before execution. |
| Presentation descriptors can become a second policy engine | Descriptors name required capability only; server returns scope, decision, policy version, expiry and evidence. |
| Generic renderer is unsafe for cash close, count, payroll, production, settlement | Use renderer families and purpose-built typed high-risk components. |
| Central correctness can create a 303-site approval bottleneck | Execute routine work locally within policy; route immutable payload-bound exceptions to the narrowest authorized queue. |
| Offline usability can imply cached authority | Only `none`, `draft_only` or `bounded_intent`; reconnect reauthorizes and shows accepted/conflict/rejected. |
| Quick setup can hide consequential defaults | Version and expose defaults/blockers; Quick and Advanced submit the same canonical command. |
| KPI drilldown can still mislead | Include metric version, scope, time/currency basis, elimination policy, missing-source classes and reconciliation state. |
| Global search can leak tenant names/counts | Server-filter before results exist; context switch clears scoped caches. |
| Reversal button can ignore downstream consumption/settlement | Server supplies a typed reversal plan; UI previews it. |
| Research breadth could trigger duplicate engines | Registry retains breadth; build order stabilizes shared posting/auth/trace contracts first. |

## Round 3 — joint resolution

Adopt one capability-rich modular backend and one context-simple task shell. Keep commercial documents, stock, accounting and settlement distinct. Use one stock book, one effective authorization service, one payload-bound approval service and one balanced source-linked posting boundary. Industry packs add typed fields/states/validation and task vocabulary without owning alternate ledgers.

The Presentation Contract is non-authoritative. It may drive placement, renderer type, semantic BN/EN guidance and result routes; it cannot contain grants, SQL/code, financial formulas, stock rules or secrets. High-risk journeys retain typed components.

The first safe slice is the deterministic synthetic demo factory: reuse A046 identities, generate two tenants/six businesses/303 sites, define stable A048/A049 expected commands, validate balanced expected math, negative cases and provenance, and never post. Drive follows only through PR #27 integration ports.
