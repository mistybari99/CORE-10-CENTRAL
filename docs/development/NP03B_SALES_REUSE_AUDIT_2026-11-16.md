## Concrete integration findings and requests

1. **Master is not built on this trunk.** `docs/architecture/CORE10_S0_SCHEMA_AND_ENGINE_PORTS.md` explicitly labels party/item/UOM/price entry points “to be built — S2”. Numbered migrations contain no canonical party, UOM, variant or price-list tables. Do not treat `a056_customers` as Master or create duplicate Master tables. NP02 must publish a scoped customer/item/variant/UOM/price-version validation contract; until then canonical production order creation must fail closed at that dependency. A disposable test double, if used, must be labelled and kept outside migrations.
2. **Sales-specific Auth actions are absent.** `0006_np01_build01_access.up.sql` restricts `can_site` and allowed/denied grant arrays to `stock.read`/`stock.post`. Those keys must not silently authorize cashier, price override, return or refund. Request NP01 canonical Sales action registration/resolution, including expiry/revocation/explicit-deny tests. NP03B must not edit NP01 grants or manufacture another ACL. A restricted owner/business_owner-only safe subset must be described as such, with site-deny enforcement, until the full action contract exists.
3. **Canonical audit is available.** Use the internal `_append_canonical_audit_v1` append service (`0008`); do not port A049 `operation_audit_v1` or CRM `a056_audit` as another operational audit chain. Order mutation and audit append must share one transaction; rollback both on failure.
4. **Approval is review, not posting.** `verify_approval_binding_v1` in `0010` verifies business/domain/action/source key/version/payload hash/expiry/approved receipt. `0011` provides routing. The Sales domain must re-read and lock its live source, enforce current Owner stages and exact source binding, and revalidate current authorization; approval alone never means stock or money posted. PR81's demo stock engine is excluded.
5. **Owner Control is available and server-side.** Feature registrations may be added in the lane's own migration block according to `CONTROL_PORT_INTEGRATION_CONTRACT.md`; no modification of Claude's existing migrations is needed. `enforced` requires the exact mapped check call plus a CI-run disabled negative test, not a catalog row alone. All replay paths must re-check live Auth and feature status before returning receipts.
6. **Number ordering is real.** Checked-in `MIGRATION_RESERVATIONS.json` still says NP03B owner “open”; the live Coordination Board claim verified by the primary engineer is authoritative for B-014. Only the trunk infrastructure owner should reconcile the shared reservation file. Reserve new `0300` onward files and do not modify old checksums or another lane's ranges.
7. **Invoice/POS/collection are missing canonical implementations.** No candidate inspected supplies the requested canonical invoice numbering, immutable issue lifecycle, cashier session/tender reconciliation, source-linked collection allocation or double-refund guard. These are missing work, not features that can be called complete because legacy files exist.
