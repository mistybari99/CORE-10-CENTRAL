## Registry workflow
REGISTRY.json is the initial research seed, not the complete feature inventory. Each row has a stable BENCH ID separate from original decision/field IDs, original references (nullable until reconciled), domain, capability, CORE10 evidence, upstream evidence, disposition, implementation maturity, priority, owning lane suggestion, action, acceptance, dependencies and research status. Expand grouped seed rows into atomic child IDs (retain parent). Link original detail IDs to one or many capabilities; reconcile every original ID to at least one destination; map all newly found upstream features to an explicit disposition. Record exact upstream ref/path/line/symbol/blob and CORE10 commit/PR/path/test/CI; source-only vs executed proof distinct. Never infer missing because a file name is absent.
Disposition: PRESERVE, RECOVER, ADOPT_CANDIDATE, MODERNIZE_CANDIDATE, ORGANIZE, ADVANTAGE_CANDIDATE, INVESTIGATE, DEFERRED, NOT_APPLICABLE (document reason/approval). Research status: SEED, SOURCE_VERIFIED, COMPARISON_VERIFIED, BUILD_READY, CLAIMED, IN_PROGRESS, BLOCKED, REVIEWED. Delivery maturity independent: UNKNOWN, PLAN, DRAFT, TRUNK, STAGING, LIVE_STAGING, PRODUCTION, OWNER_ACCEPTED; don't conflate CI with hosted readiness. Add separate test and evidence arrays as work expands.
Views (not duplicate registries): R01 preservation/traceability, R02 missing feature, R03 competitive advantage, R04 security/correctness, R05 build improvement, R06 modernization/performance, R07 upstream bug/regression, R08 release/agent progress. Every discovered capability remains visible even if deferred.

## Modernization experiment gate (per capability)
- Before: reproduce current behavior at pinned commit; describe purpose and invariants; fixed synthetic dataset; record environment, cache state, workload, repetitions, error rate and p50/p95/p99 where meaningful, DB query count/EXPLAIN, locks/concurrency, throughput, mobile time/taps/bytes. For finance/stock record exact decimal outputs, reconciliation and audit parity. No invented baseline/target or cross-stack timing comparisons.
- Compare upstream implementation/design at pinned ref, alternative native PostgreSQL/JS approach, maintainability, license, cost and risk. Choose reuse/port/extend/refactor/new; document decision and alternatives.
- After: run same fixture and environment, original acceptance and new adversarial regression tests; compare before/after. Require 100% mapped original behavior or documented Owner-approved policy decision; no regressions in auth, calculations, audit, idempotency or accessibility. Propose per-item measurable target AFTER baseline; no performance gain claim without measurements. Validate 10/100/400-site scoped lists and representative cross-group workload with seeded data; do not equate provisioning cap with load capacity.
- Release: exact-head PG17 up/down/up, control registry, RLS/ACL/search_path, cross-tenant/business/site, revocation while waiting, duplicate/replay, race/rollback, signed GoTrue, browser 390/1440 bn/en, legacy guard. Compare scoped staging ledger/checksum, backup/rehearse, integration approval, rollback, public test where allowed. On failure stop and record remediation. Never weaken tests.
