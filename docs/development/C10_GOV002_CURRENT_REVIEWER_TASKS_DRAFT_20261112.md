# GOV-002 — My Current Review Tasks (Preview-only)

This small additive read-only PostgreSQL `SECURITY DEFINER` RPC solves a known usability gap in the owner/maker-only approval inbox: reviewers assigned to the current stage can find the *specific* request when it is their turn without opening all manager/tenant approval records. It does **not** relax existing security-invoker approval status/report policies or grant permission to approve.

`my_routed_review_tasks_v2(p_business)` takes **only** a business ID, derives the signed actor using canonical `actor_uid`, requires current same-business membership or tenant owner, checks live pending/expiry, exactly required current stage role (business owner/manager/tenant owner), prior-vote reuse, maker conflict, optional Build01 membership `valid_until`, and bounded stage-1 delegation proof. Returns at most 100 tasks, source reference/version and stage counters, **no raw payload or exception reasons**, and no cross-business aggregate. The existing `decide_approval` RPC still independently revalidates maker-checker and current access under a row lock before any receipt.

Negative PG17 tests cover maker, premature intermediate manager, site-only user, foreign tenant, revoked manager, current business owner, intermediate manager and final tenant owner. The opt-in signed review client exposes `listReviewerTasks`, protected by the PR91 session guard. Synthetic JWT-claim PostgreSQL evidence only, NOT actual GoTrue/A034 approval-specific allow/explicit deny, hosted Supabase security certification, or a production staff inbox. Codex Build01 and Claude GOV003 files, main, original Islamia ERP D051/R130, SG and real data remain unchanged.
