## Implementation decisions
**IMPL-001 Base and branch.** The mandate says to base on the reviewed foundation if A021–A023 source is needed. Verified: `internal/enterprise-sql/c10_a02{1,2,3}_*.sql` live on PR #7, **not on `main`**; PR #7/#60/#59/#73/#67 were not touched, rebased or relied on. The scenario SQL is therefore self-contained and reads scope from two small stand-in views (`business_source`, `site_source`, `grant_source`) that a staging step must re-point at canonical A018/A021/A034 objects. Branch name is the harness-assigned Claude-owned branch, not `feature/c10-a025-simulation-isolated-draft-v1` (policy requires the assigned branch). PR targets `main` as a draft; nothing merges.
**IMPL-002 Runtime.** Repo is dependency-free CommonJS/vanilla JS with Node `assert` tests; no React/bundler was introduced. A 90-line in-repo bundler wraps the same CommonJS engine for the browser (`dist/` is generated and CI-checked for staleness).
**IMPL-003 Money.** BigInt fixed point, no JS float in money math (guard test greps for it). Display rounding is half-away-from-zero at the output's declared places; analysis uses the unrounded `exact` values. Loan schedules round interest and instalments to 2 dp each month and the last instalment absorbs the remainder so the balance closes to exactly 0.
**IMPL-004 Unknown is not zero.** Missing required input ⇒ `readiness: needs_input`, `outputs: null`. Optional inputs without a default stay `null` and the dependent output is `null` (e.g. tax, cash bridge). Defaulted optional inputs are labelled `assumption`, so data-quality grade never reads as "actual" by accident. Grade `ALL_INPUTS_MARKED_ACTUAL_UNVERIFIED` still has `certifiedFinancialFact:false`.
**IMPL-005 Versioning.** `registerModel` refuses to overwrite. `formulaHash = sha256(formulaText + calculate.toString() + input schema)`; CI fails if any hash changes without a new version. M01 ships v1 and v2 (channel fee) as the living migration example; saved scenarios pin the version resolved at creation; `compareModelVersions` and `reproduce` never rewrite history.
**IMPL-006 Honest status.** `implemented_tested` requires ≥2 goldens including ≥1 adverse case, negative tests and result-source tests. **M18 is `partial`** because no verified jurisdiction rate/source registry exists; it only applies owner-supplied rules marked `config_verified` **and** carrying a `source_ref`, otherwise the amount is unknown (never defaulted, no built-in VAT/tax rate).
**IMPL-007 Financing semantics (A022/A023 caution).** `profit_share_bps=1400` = 14 % of *positive period profit*, never 14 % interest on principal. Fixed contractual payments are liabilities payable in loss months; bank debt separates principal (financing cashflow) from interest (P&L); equity has no fixed obligation. Output always states `guaranteed_return:false`, `legal_or_sharia_classification:"NOT_ASSERTED"`. Profit is used as a *cash proxy* and flagged as such. A022/A023 figures are `MANUAL_UNVERIFIED` seeds and must never be relabelled as actual POS profit.
**IMPL-008 Persistence security.** Authenticated role gets **SELECT only** (through RLS) and `EXECUTE` on ten RPCs; no INSERT/UPDATE/DELETE anywhere, no privileges for `sim_anon`, none on operational tables. RPCs are `SECURITY DEFINER` with `search_path = pg_catalog, c10_sim`, explicit capability checks, existence-hiding `NOT_FOUND`, `FOR UPDATE` row locks, `REVOKE … FROM PUBLIC`. Tables are not `FORCE ROW LEVEL SECURITY` because the definer owner must read them; a production owner role must therefore be a dedicated non-login role.
**IMPL-009 Trust boundary of results (known gap).** Calculation runs client/engine side; the database verifies that a submitted run uses the *pinned model version's formula hash* and the *saved input snapshot*, forbids side effects and stores it immutably — but it does **not recompute** the numbers. A malicious client holding `sim.run` could therefore store a forged `result`. Mitigation (not built): recompute in a trusted function runtime before `record_run`. Tracked in the handover as the smallest next security step.
**IMPL-010 Apply is impossible.** There is no `applied` state, no write method and no approval-engine routing. `apply_to_live` returns `{applied:false, reason:"DISABLED_ADVISORY_ONLY"}` and DB check constraints force `advisory_only=true`, `apply_state='DISABLED'`. The approval adapter accepts only `scenario_advisory_proposal` and refuses module-visibility/generic mutations (the A021 module-visibility request/decision APIs are not a scenario-approval service).
**IMPL-011 Separation of duties.** The scenario owner cannot approve/reject their own scenario (JS + SQL). `sim.review`/`sim.propose` are separate capabilities; investors get only `sim.read_shared` on explicitly shared scenarios.
**IMPL-012 UI persistence.** The demo UI persists scenarios in `localStorage` (hash-chain verified on restore); it is **not** wired to the SQL schema. SQL persistence is tested independently. Wiring them requires a trusted API layer (see IMPL-009).
**IMPL-013 Uncertainty.** No Monte-Carlo or probability output exists. Scenario ranges are the only uncertainty facility; X01 is registered `research_only` so the gap is visible in the registry.
**IMPL-014 Examples.** Demo inputs are generated from the same golden fixtures the tests use (`dist/c10-sim-examples.js`), so every on-screen example is a verified case. Industry coverage in the demo: sweets/bakery (branch M16, BOM M07), paint & wholesale (supplier M06, working capital M10), construction (BOQ M15), plus loan/investor (M13/M14), consolidation (M19), template (M20).
**IMPL-015 REV-009.** No sweets/Islamia branded formula, table or label is reused; a guard test greps the module for brand/legacy strings and imports.
**IMPL-016 Scope hygiene.** The guard test fails if the PR touches anything outside `modules/simulation/`, `tests/c10_a025/`, `docs/development/C10_A025_*`, or the A025 workflow. No live navigation, service worker, manifest or legacy ERP file is changed.

## Key formulas (full text is in each model's `formulaText`, shown in the UI "Formula & version")
- Pricing: `net=price·(1−d)`, `eff=cost/(1−waste)`, margin=`contrib/net`, markup=`contrib/eff`. Break-even: `(fixed+target)/(price−vc)`, infeasible if `≤0`.
- Cashflow: `receipts[m]=revenue[m−lag]`; principal & capex are cash only; profit=`rev−opcost−interest`; flag months with profit>0 and net cash<0.
- Branch (M16): deposit, capex, principal, investor fixed payment are **not** P&L; opening stock is consumed by COGS first (no double count); lowest cash is evaluated from the setup row.
- NPV `Σcf/(1+r)^t`; IRR only if exactly one root in (−90 %, +500 %]; otherwise `NO_SIGN_CHANGE | NO_ROOT_IN_RANGE | MULTIPLE_ROOTS`.
- Consolidation: Σ external only; internal revenue − internal cost must be 0 else `ELIMINATION_MISMATCH`; any other-tenant site rejects the whole run.
